Nicht für 1.7 alpha8 und neuer. Ab alpha8 wurde die Mechanik umgebaut: fakelib2 wird nur noch im Backport-Ordner gesucht, und statt zweier Schichten läuft alles über einen Cache. Dafür gilt die separate Anleitung. Unsicher, welche Version läuft? Drei Prüfungen am Seitenende.

01

Was beim Spielstart passiert

Der Ablauf läuft vollautomatisch ab, sobald der Watcher ein startendes Spiel erkennt.

  1. Der Watcher meldet PID und TITLE_ID.
  2. Gesucht wird die Sandbox /mnt/sandbox/<TITLE_ID>_NNN mit der höchsten Nummer.
  3. Quelle wählen: app0/fakelib2 hat Vorrang, sonst app0/fakelib. Es wird immer nur einer von beiden genommen.
  4. Ziel ist der erste Ordner in der Sandbox, der nicht app0 heißt und ein gültiges common/lib hat.
  5. Einhängen per unionfs — copymode=transparent, notime, fnodup.
  6. Ist eine globale fakelib aktiv, kommt sie als zweite Schicht dazu.
  7. Beim Spielende werden die Schichten in umgekehrter Reihenfolge entfernt.

In dieser Version werden die Ordner aus der laufenden Sandbox gelesen — alles, was in app0 landet, zählt. Das gilt für Dateien aus dem Spiel-Dump ebenso wie für Dateien aus dem backports-Ordner, denn der Backport wird über das Spiel gelegt und erscheint dadurch ebenfalls in app0.

02

Ordnerstruktur

Zwei Wege führen zum Ziel. Beide funktionieren in dieser Version gleichwertig — Weg B lässt den Spiel-Dump unangetastet.

Weg A · im Spiel-Dump oder Image 
<Spielordner oder Image-Inhalt>/
├─ eboot.bin
├─ sce_sys/param.json
├─ fakelib2/   ← wird bevorzugt
│  └─ libSceXxx.sprx
└─ fakelib/    ← Fallback
   └─ libSceXxx.sprx
Weg B · als Backport, ohne das Spiel anzufassen 
<scanpath>/backports/<TITLE_ID>/
└─ fakelib2/
   └─ libSceXxx.sprx

Beispiel:
/data/homebrew/backports/PPSA01234/

Regeln

Ordnernamen exakt fakelib2 bzw. fakelib, klein geschrieben. Liegt fakelib2 vor, wird fakelib vollständig ignoriert — auch dann, wenn fakelib2 leer ist. Befülle immer nur einen der beiden.

Der backports-Ordner wird beim normalen Scan ignoriert. Liefern mehrere Scan-Pfade denselben Titel, gewinnt der Scan-Pfad des Spiels; sonst entscheidet die Reihenfolge der scanpath-Einträge.

03

Globale fakelib

Ein Ordner für alle Spiele, standardmäßig aktiv: /data/shadowmount/fakelib/. Existieren global und spiel-eigen, werden zwei Schichten übereinandergelegt. Für unionfs gilt: zuletzt eingehängt liegt oben und gewinnt.

Standard

global_fakelib_priority=game

1 · global→ 2 · Spiel

Die fakelib des Spiels gewinnt.

Alternative

global_fakelib_priority=global

1 · Spiel→ 2 · global

Die globale fakelib gewinnt.

Zeigen beide Pfade auf denselben Ordner, wird nur einmal eingehängt. Schlägt eine Schicht fehl, werden alle bereits gesetzten wieder entfernt — es entsteht nie ein halber Stapel.

Einen Cache gibt es in dieser Version nicht. Ebenso wenig Emulator-Updates oder AMPR-Download — das kam erst mit alpha8.

04

Einstellungen

Alles steht in /data/shadowmount/config.ini. Die Datei ist optional — fehlt sie, wird sie beim Start aus config.ini.example angelegt.

SchlüsselStandardBedeutung
backport_fakelib1Master-Schalter. 0 schaltet auch die globale fakelib aus.
global_fakelib1Globalen Ordner als zweite Schicht mitverwenden.
global_fakelib_path/data/shadowmount/fakelibOrt des globalen Ordners.
global_fakelib_prioritygamegame oder global.
global_fakelib_exclude—Wiederholbar, max. 128 Title-IDs. Schließt Titel von der globalen fakelib aus; die spiel-eigene bleibt aktiv.

Beispiel

backport_fakelib=1
global_fakelib=1
global_fakelib_path=/data/shadowmount/fakelib
global_fakelib_priority=game
global_fakelib_exclude=PPSA01234

Als Werte gehen 1/0, true/false, yes/no, on/off. Groß-/Kleinschreibung der Schlüssel ist egal.

05

Schritt für Schritt

Von null bis zur Meldung „Spiel backportiert“.

  1. BackPork-Payload deaktivieren. Parallelbetrieb kollidiert.
  2. Spiel-Dump ablegen in einem Scan-Pfad. Ordner-Dumps brauchen sce_sys/param.json.
  3. Backport-Dateien erzeugen — externes Werkzeug, nicht Teil von ShadowMount+.
  4. In einen Ordner fakelib2 legen — im Spielordner selbst oder unter <scanpath>/backports/<TITLE_ID>/. Beides funktioniert hier.
  5. Optional: globale Bibliotheken nach /data/shadowmount/fakelib/.
  6. Config setzen — vor dem Spielstart.
  7. Payload starten (Port 9021 oder autoload.txt) und auf die Kachel warten.
  8. Spiel starten. Meldung: „Spiel backportiert: <TITLE_ID>“. Bei reinem Global-Overlay bleibt sie aus — das ist kein Fehler.
06

Stolperfallen

Vier Punkte, an denen es in dieser Version regelmäßig klemmt.

Nur ein Spiel gleichzeitig

Es wird genau eine fakelib-Sitzung mit maximal zwei Schichten verwaltet. Beim Spielwechsel wird der alte Mount zuerst abgeräumt; scheitert das, bekommt das neue Spiel keine fakelib.

Config nicht während des Spiels ändern

Jede Änderung an einem fakelib-Schlüssel entfernt sofort alle Overlays — auch beim laufenden Spiel.

Ohne common/lib passiert nichts

Stiller Abbruch: keine Meldung, kein Log-Eintrag.

Sandbox-Auswahl

Bei mehreren <TITLE_ID>_NNN gewinnt die höchste Nummer. Alte Sandbox-Reste stören nicht.

08

Welche Version habe ich?

Drei schnelle Prüfungen — jede allein genügt.

Steht update_emulators in config.ini.example?

ja neue Version (alpha8+)
nein alte Version — diese Anleitung

Gibt es den Ordner /data/shadowmount/cache/?

ja neue Version
nein alte Version (oder noch kein Cache nötig)

Steht im Log je [FAKELIB] using cache for?

ja neue Version
nein alte Version — die Zeile gibt es dort nicht

Gilt für ShadowMountPlus bis einschließlich 1.7 alpha6.

Ab 1.7 alpha8 gilt die separate Anleitung: fakelib2 wird nur noch im Backport-Ordner gesucht, und statt zweier Schichten kommt ein Cache zum Einsatz.
