Not for 1.7 alpha8 and newer. Starting with alpha8, the mechanism was reworked: lookups happen at fixed locations, first in the backport folder, then in the game (a fakelib2 in the game folder is skipped from alpha8 through alpha13fix1 and counts again from 1.7beta1), and instead of two layers everything goes through a cache. The separate guide applies there. Not sure which version is running? Three checks at the end of the page.

01

What happens when a game starts

The process runs fully automatically as soon as the watcher detects a starting game.

  1. The watcher reports PID and TITLE_ID.
  2. The sandbox /mnt/sandbox/<TITLE_ID>_NNN with the highest number is looked up.
  3. Choose the source: app0/fakelib2 takes precedence, otherwise app0/fakelib. Only one of the two is ever used.
  4. The target is the first folder in the sandbox that is not named app0 and has a valid common/lib.
  5. Mounting via unionfs — copymode=transparent, notime, fnodup.
  6. If a global fakelib is active, it is added as the second layer.
  7. When the game ends, the layers are removed in reverse order.

In this version, the folders are read from the running sandbox — everything that ends up in app0 counts. This applies to files from the game dump as well as to files from the backports folder, because the backport is laid over the game and therefore also appears in app0.

02

Folder structure

Two ways lead to the goal. Both work equally in this version — way B leaves the game dump untouched.

Way A · in the game dump or image 
<game folder or image contents>/
├─ eboot.bin
├─ sce_sys/param.json
├─ fakelib2/   ← preferred
│  └─ libSceXxx.sprx
└─ fakelib/    ← fallback
   └─ libSceXxx.sprx
Way B · as a backport, without touching the game 
<scanpath>/backports/<TITLE_ID>/
└─ fakelib2/
   └─ libSceXxx.sprx

Example:
/data/homebrew/backports/PPSA01234/

Rules

Folder names exactly fakelib2 or fakelib, lowercase. If fakelib2 is present, fakelib is ignored completely — even if fakelib2 is empty. Always fill only one of the two.

The backports folder is ignored during the normal scan. If several scan paths supply the same title, the game's scan path wins; otherwise the order of the scanpath entries decides.

03

Global fakelib

One folder for all games, active by default: /data/shadowmount/fakelib/. If both a global and a game-specific one exist, two layers are stacked on top of each other. For unionfs, the rule is: the layer mounted last is on top and wins.

Default

global_fakelib_priority=game

1 · global→ 2 · game

The game's fakelib wins.

Alternative

global_fakelib_priority=global

1 · game→ 2 · global

The global fakelib wins.

If both paths point to the same folder, it is mounted only once. If one layer fails, all layers already set are removed again — a half-built stack never results.

There is no cache in this version. Neither are there emulator updates or an AMPR download — those only came with alpha8.

04

Settings

Everything is in /data/shadowmount/config.ini. The file is optional — if it is missing, it is created from config.ini.example at startup.

KeyDefaultMeaning
backport_fakelib1Master switch. 0 also turns off the global fakelib.
global_fakelib1Also use the global folder as the second layer.
global_fakelib_path/data/shadowmount/fakelibLocation of the global folder.
global_fakelib_prioritygamegame or global.
global_fakelib_exclude—Repeatable, max. 128 title IDs. Excludes titles from the global fakelib; the game's own stays active.

Example

backport_fakelib=1
global_fakelib=1
global_fakelib_path=/data/shadowmount/fakelib
global_fakelib_priority=game
global_fakelib_exclude=PPSA01234

Accepted values are 1/0, true/false, yes/no, on/off. Key names are case-insensitive.

05

Step by step

From zero to the message "Game backported".

  1. Disable the BackPork payload. Running both in parallel causes conflicts.
  2. Place the game dump in a scan path. Folder dumps need sce_sys/param.json.
  3. Create the backport files — external tool, not part of ShadowMount+.
  4. Put them in a folder named fakelib2 — in the game folder itself or under <scanpath>/backports/<TITLE_ID>/. Both work here.
  5. Optional: global libraries to /data/shadowmount/fakelib/.
  6. Set the config — before starting the game.
  7. Start the payload (port 9021 or autoload.txt) and wait for the tile.
  8. Start the game. Message: "Game backported: <TITLE_ID>". With a global overlay only, it does not appear — that is not an error.
06

Pitfalls

Four points where this version regularly gets stuck.

Only one game at a time

Exactly one fakelib session with at most two layers is managed. When switching games, the old mount is cleaned up first; if that fails, the new game gets no fakelib.

Do not change the config while a game is running

Any change to a fakelib key immediately removes all overlays — even while the game is running.

Without common/lib nothing happens

Silent abort: no message, no log entry.

Sandbox selection

If there are several <TITLE_ID>_NNN, the highest number wins. Old sandbox leftovers do no harm.

07

Reading the log

File /data/shadowmount/debug.log, filter [FAKELIB].

LineMeaning
game libraries mounted for <ID>: …Game fakelib is active.
global libraries mounted for <ID>: …Global fakelib is active.
<label> mount failed for <ID> …Mounting failed, the stack is rolled back.
global path unavailable for <ID>Global path is missing or not readable.

no lineSandbox cannot be resolved, no fakelib folder, or backport_fakelib=0.
08

Which version do I have?

Three quick checks — any one is enough.

Is update_emulators in config.ini.example?

yes new version (alpha8+)
no old version — this guide

Does the folder /data/shadowmount/cache/ exist?

yes new version
no old version (or no cache needed yet)

Does the log ever contain [FAKELIB] using cache for?

yes new version
no old version — that line does not exist there

Applies to ShadowMountPlus up to and including 1.7 alpha6.

From 1.7 alpha8 on, the separate guide applies: lookups happen at fixed locations (a fakelib2 in the game folder only again from 1.7beta1), and a cache is used instead of two layers.
