Monter les backports Comment ShadowMount+ remplace les bibliothèques d'un jeu — vérifié sur le code source de la 1.7 alpha6.

Valable jusqu'à la 1.7 alpha6 incluse unionfs · deux couches pas de cache État : 22 août 2026
!

Ne s'applique pas à la 1.7 alpha8 et aux versions suivantes. À partir de l'alpha8, le mécanisme a été remanié : la recherche se fait à des emplacements fixes, d'abord dans le dossier Backport, puis dans le jeu (un fakelib2 dans le dossier du jeu est ignoré par les versions alpha8 à alpha13fix1, il est de nouveau pris en compte à partir de la 1.7beta1), et, au lieu de deux couches, tout passe par un cache. Le guide distinct s'applique alors. Un doute sur la version en cours d'exécution ? Trois vérifications en bas de page.

01

Ce qui se passe au lancement du jeu

Le déroulement est entièrement automatique dès que le watcher détecte le lancement d'un jeu.

  1. Le watcher communique le PID et le TITLE_ID.
  2. La sandbox /mnt/sandbox/<TITLE_ID>_NNN portant le numéro le plus élevé est recherchée.
  3. Choix de la source : app0/fakelib2 est prioritaire, sinon app0/fakelib. Un seul des deux à la fois est utilisé.
  4. La cible est le premier dossier de la sandbox qui ne s'appelle pas app0 et qui contient un common/lib valide.
  5. Montage par unionfs — copymode=transparent, notime, fnodup.
  6. Si une fakelib globale est active, elle s'ajoute comme seconde couche.
  7. À la fin du jeu, les couches sont retirées dans l'ordre inverse.

Dans cette version, les dossiers sont lus depuis la sandbox en cours d'exécution — tout ce qui atterrit dans app0 compte. Cela vaut aussi bien pour les fichiers du dump du jeu que pour ceux du dossier backports, car le backport est superposé au jeu et apparaît donc lui aussi dans app0.

02

Structure des dossiers

Deux voies mènent au but. Les deux fonctionnent de façon équivalente dans cette version — la voie B laisse le dump du jeu intact.

Voie A · dans le dump du jeu ou l'image 
<dossier du jeu ou contenu de l'image>/
├─ eboot.bin
├─ sce_sys/param.json
├─ fakelib2/   ← prioritaire
│  └─ libSceXxx.sprx
└─ fakelib/    ← repli
   └─ libSceXxx.sprx
Voie B · comme backport, sans toucher au jeu 
<scanpath>/backports/<TITLE_ID>/
└─ fakelib2/
   └─ libSceXxx.sprx

Exemple :
/data/homebrew/backports/PPSA01234/

Règles

Les noms de dossier sont exactement fakelib2 ou fakelib, en minuscules. Si fakelib2 existe, fakelib est entièrement ignoré — même si fakelib2 est vide. Ne remplir toujours qu'un seul des deux.

Le dossier backports est ignoré lors de l'analyse normale. Si plusieurs chemins de scan fournissent le même titre, le chemin de scan du jeu l'emporte ; sinon, l'ordre des entrées scanpath décide.

03

fakelib globale

Un dossier pour tous les jeux, actif par défaut : /data/shadowmount/fakelib/. Si une fakelib globale et une fakelib propre au jeu existent, deux couches sont superposées. Pour unionfs, la règle est : le dernier monté se trouve au-dessus et l'emporte.

Par défaut

global_fakelib_priority=game

1 · globale→ 2 · jeu

La fakelib du jeu l'emporte.

Alternative

global_fakelib_priority=global

1 · jeu→ 2 · globale

La fakelib globale l'emporte.

Si les deux chemins pointent vers le même dossier, le montage n'a lieu qu'une seule fois. Si une couche échoue, toutes celles déjà posées sont retirées — il n'y a jamais de pile à moitié montée.

Il n'existe pas de cache dans cette version. Pas non plus de mises à jour d'émulateurs ni de téléchargement AMPR — cela n'est arrivé qu'avec l'alpha8.

04

Paramètres

Tout se trouve dans /data/shadowmount/config.ini. Le fichier est facultatif — s'il manque, il est créé au démarrage à partir de config.ini.example.

CléValeur par défautSignification
backport_fakelib1Interrupteur principal. 0 désactive aussi la fakelib globale.
global_fakelib1Utiliser aussi le dossier global comme seconde couche.
global_fakelib_path/data/shadowmount/fakelibEmplacement du dossier global.
global_fakelib_prioritygamegame ou global.
global_fakelib_exclude—Répétable, 128 title-ID au maximum. Exclut des titres de la fakelib globale ; celle propre au jeu reste active.

Exemple

backport_fakelib=1
global_fakelib=1
global_fakelib_path=/data/shadowmount/fakelib
global_fakelib_priority=game
global_fakelib_exclude=PPSA01234

Valeurs acceptées : 1/0, true/false, yes/no, on/off. La casse des clés n'a pas d'importance.

05

Pas à pas

De zéro jusqu'au message « Jeu backporté ».

  1. Désactiver le payload BackPork. Un fonctionnement en parallèle provoque des conflits.
  2. Placer le dump du jeu dans un chemin de scan. Les dumps sous forme de dossier nécessitent sce_sys/param.json.
  3. Générer les fichiers de backport — outil externe, ne faisant pas partie de ShadowMount+.
  4. Les placer dans un dossier fakelib2 — dans le dossier du jeu lui-même ou sous <scanpath>/backports/<TITLE_ID>/. Les deux fonctionnent ici.
  5. Facultatif : bibliothèques globales dans /data/shadowmount/fakelib/.
  6. Définir la config — avant le lancement du jeu.
  7. Lancer le payload (port 9021 ou autoload.txt) et attendre la vignette.
  8. Lancer le jeu. Message : « Jeu backporté : <TITLE_ID> ». Avec une simple superposition globale, il n'apparaît pas — ce n'est pas une erreur.
06

Pièges courants

Quatre points où cela coince régulièrement dans cette version.

Un seul jeu à la fois

Une seule session fakelib, avec au maximum deux couches, est gérée. Lors d'un changement de jeu, l'ancien montage est d'abord démonté ; si cela échoue, le nouveau jeu ne reçoit aucune fakelib.

Ne pas modifier la config pendant le jeu

Toute modification d'une clé fakelib retire immédiatement tous les overlays — même pendant que le jeu tourne.

Sans common/lib, rien ne se passe

Abandon silencieux : aucun message, aucune entrée dans le journal.

Choix de la sandbox

Lorsqu'il existe plusieurs <TITLE_ID>_NNN, le numéro le plus élevé l'emporte. Les anciens restes de sandbox ne gênent pas.

07

Lire le journal

Fichier /data/shadowmount/debug.log, filtre [FAKELIB].

LigneSignification
game libraries mounted for <ID>: …La fakelib du jeu est active.
global libraries mounted for <ID>: …La fakelib globale est active.
<label> mount failed for <ID> …Échec du montage, la pile est annulée.
global path unavailable for <ID>Le chemin global est absent ou illisible.
global path is not a directory for <ID>Le chemin pointe vers un fichier.
handoff active mount pid=X -> pid=YChangement de jeu, l'ancien montage est démonté.
unmount deferred for …Cible encore occupée (EBUSY).
aucune ligneSandbox non résolue, aucun dossier fakelib, ou backport_fakelib=0.
