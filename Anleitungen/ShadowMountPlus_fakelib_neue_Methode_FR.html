!

Pas pour 1.7 alpha6 et antérieures. Dans ces versions, les dossiers sont encore lus depuis la sandbox en cours d'exécution, et deux couches se superposent. C'est la procédure séparée qui s'applique. Erreur la plus fréquente lors du passage : un fakelib2 placé dans le dossier du jeu est ignoré de alpha8 à alpha13fix1 – sans aucun message. À partir de 1.7beta1, il est de nouveau lu et l'emporte alors sur un fakelib placé à côté. Vous ne savez pas quelle version est installée ? Vérifications en bas de page.

01

Ce qui se passe au démarrage du jeu

Le déroulement démarre automatiquement dès que le watcher détecte un jeu qui se lance. La recherche ne se fait plus dans la sandbox en cours d'exécution, mais à des emplacements fixes – et un cache est créé avant le montage.

  1. Le watcher signale le PID et le TITLE_ID du jeu qui démarre.
  2. La recherche suit un ordre fixe : d'abord le dossier de backport, puis la source du jeu ; le premier résultat l'emporte, et un seul dossier est toujours retenu (section 02).
  3. S'il s'agit d'un fakelib2 – provenant du dossier de backport ou, à partir de 1.7beta1, du jeu –, il est monté directement et exclusivement – sans cache, sans fichiers d'émulateur, sans fakelib globale.
  4. Sinon, un cache est créé sous /data/shadowmount/cache/<TITLE_ID>/fakelib/ : la fakelib du jeu, plus la fakelib globale et les fichiers d'émulateur correspondants (section 03).
  5. Le cache n'est reconstruit que si l'une de ses sources a changé ; sinon, le cache existant est utilisé.
  6. Le montage se fait dans la sandbox du jeu, vers common/lib.
  7. À la fin du jeu, le montage est retiré.

À partir de cette version, l'emplacement d'un dossier compte, et pas seulement son nom. La lecture se fait dans le dossier de backport et dans la source du jeu elle-même – et plus dans ce qui s'assemble dans la sandbox sous app0.

02

Ordre de recherche

Quatre emplacements, dans cet ordre. Le premier dossier présent l'emporte – même s'il est vide ; ce qui suivrait n'est pas pris en compte.

  1. <scanpath>/backports/<TITLE_ID>/fakelib2/ – l'emporte sur tout le reste et est monté exclusivement depuis alpha10.
  2. <scanpath>/backports/<TITLE_ID>/fakelib/
  3. <Spielquelle>/fakelib2/ – seulement à partir de 1.7beta1, également exclusif. 1.7 alpha8 à alpha13fix1 l'ignorent sans message.
  4. <Spielquelle>/fakelib/ – agit dans toutes les versions, tant qu'aucun fakelib2 ne se trouve à côté.
Voie A · en tant que backport, le jeu reste intact 
<scanpath>/backports/<TITLE_ID>/
└─ fakelib/
   └─ libSceXxx.sprx

Exemple :
/data/homebrew/backports/PPSA01234/fakelib/
Voie B · dans le dump du jeu ou l'image 
<dossier du jeu ou contenu de l'image>/
├─ eboot.bin
├─ sce_sys/param.json
├─ fakelib/    ← fonctionne dans toutes les versions
│  └─ libSceXxx.sprx
└─ fakelib2/   ← ne pas la placer à côté !

Règles

Noms de dossier exacts : fakelib ou fakelib2, en minuscules. Dans le dossier du jeu, 1.7beta1 et les versions plus récentes lisent d'abord fakelib2, puis fakelib ; 1.7 alpha8 à alpha13fix1 y lisent uniquement fakelib et ignorent un fakelib2 sans message. Le seul choix sûr dans toutes les versions est donc un unique dossier fakelib. Dans le dossier de backport, fakelib2 passe avant fakelib ; si les deux s'y trouvent, fakelib2 l'emporte.

Le dossier backports est ignoré lors de l'analyse normale. Un backport agit sur le jeu correspondant depuis n'importe quel chemin de scan ; si plusieurs chemins de scan fournissent le même titre, c'est le chemin de scan du jeu qui l'emporte, sinon l'ordre des entrées scanpath. Les emplacements habituels sont /data/homebrew/backports/<TITLE_ID>/ et /data/etaHEN/games/backports/<TITLE_ID>/. À partir de 1.7beta6, un complément peut suivre le Title-ID (backports/<TITLE_ID> Spielname/) : au sein d'un chemin de scan, le dossier qui s'appelle exactement <TITLE_ID> l'emporte ; s'il n'existe pas, ShadowMount+ prend, parmi les dossiers dont le nom commence par le Title-ID complet, le premier dans l'ordre des octets (la casse compte ; les fichiers ne comptent pas). Si, à côté d'un dossier avec complément, il existe aussi un dossier portant le nom nu, celui avec complément n'est plus lu. À partir de 1.7beta3, /data/homebrew/backports/<TITLE_ID>/ est toujours parcouru en dernier – même si des entrées scanpath personnalisées omettent /data/homebrew. Les jeux ne sont donc pas recherchés à cet endroit.

PKG installés (à partir de 1.7beta2) : un jeu installé sous forme de PKG reçoit lui aussi son dossier de backport <scanpath>/backports/<TITLE_ID>/. Peu avant le démarrage du jeu, ShadowMount+ incorpore son contenu entier dans le app0 du paquet – les fichiers un par un, et les sous-dossiers que le paquet n'a pas en bloc, au maximum 256 entrées par jeu. Le paquet lui-même n'est pas modifié. Ensuite, fakelib2 ou fakelib est monté comme d'habitude. Jusqu'à 1.7, un backport externe était ignoré pour les PKG installés ; seul ce qui se trouvait dans le paquet comptait.

Lors de l'intégration (BACKPORT, AMPR EMU), ce programme crée toujours un dossier fakelib – il agit aux deux emplacements et dans toutes les versions. S'il y a déjà un fakelib2 dans le jeu, il avertit au préalable.

03

Cache, émulateurs et fakelib globale

Au lieu de superposer des couches, ShadowMount+ copie tout dans un cache sous /data/shadowmount/cache/<TITLE_ID>/fakelib/ avant le démarrage. Ce qui est copié en dernier l'emporte à nom de fichier identique – l'ordre est défini par global_fakelib_priority.

Par défaut

global_fakelib_priority=game

1 · globale→ 2 · jeu→ 3 · émulateur

Le fichier du jeu l'emporte sur le fichier global. Les fichiers d'émulateur n'y remplacent que les noms que le jeu apporte déjà.

Alternative

global_fakelib_priority=global

1 · jeu→ 2 · émulateur→ 3 · globale

Le fichier global l'emporte – même sur un fichier d'émulateur du même nom, qui n'est alors même pas copié.

Fichiers d'émulateur (update_emulators=1) : un fichier de /data/shadowmount/emus n'est repris que si la fakelib du jeu contient un fichier du même nom. Si un nom n'existe que dans le dossier global ou nulle part, il est ignoré. Pour un jeu sans libSceAmpr.sprx, cette voie seule n'apporte donc rien. À partir de 1.7beta2, cela ne vaut que pour les jeux provenant de dossiers et d'images – les PKG installés ne reçoivent pas de fichiers d'émulateur.

Mise à jour automatique d'AMPR (auto_update_ampr=1, désactivée par défaut) : 30 secondes après le démarrage, puis toutes les quatre heures, ShadowMount+ vérifie s'il existe une libSceAmpr.sprx plus récente et la dépose dans emulators_path. Si elle y est totalement absente, elle est récupérée tout de suite. Tant qu'un jeu est monté, le téléchargement attend. Elle n'arrive dans le jeu que par les fichiers d'émulateur – donc seulement si la fakelib de celui-ci contient déjà une libSceAmpr.sprx.

Fakelib globale : s'il existe une fakelib globale et une fakelib propre au jeu, les deux sont réunies dans le cache. S'il n'y a pas de fakelib propre au jeu, le dossier global est monté directement. Avec global_fakelib_exclude, on peut en exclure certains titres.

Depuis alpha10 : un fakelib2 de backport est monté directement et exclusivement. Ni les fichiers d'émulateur ni la fakelib globale n'y remplacent ou n'y ajoutent quoi que ce soit.

Le cache est reconstruit dès que la fakelib du jeu, la fakelib globale ou les fichiers d'émulateur changent. Si un jeu n'est pas lancé pendant sept jours, son cache expire.

05

Pas à pas

De zéro jusqu'au message « Jeu backporté ».

  1. Désactiver le payload BackPork. Un fonctionnement en parallèle provoque des conflits.
  2. Placer le jeu dans un chemin de scan – sous forme de dossier (avec sce_sys/param.json) ou d'image.
  3. Générer les bibliothèques – par exemple avec ce programme (BACKPORT ou AMPR EMU). Il crée toujours un dossier fakelib.
  4. Déposer. En tant que backport sous <scanpath>/backports/<TITLE_ID>/fakelib/, le jeu reste intact. Dans le jeu lui-même – c'est ainsi que ce programme l'intègre lors de la création – seul fakelib agit.
  5. Facultatif : bibliothèques globales directement dans /data/shadowmount/fakelib/, fichiers d'émulateur directement dans /data/shadowmount/emus/ – dans les deux cas sans sous-dossier.
  6. Définir la config – avant le démarrage du jeu.
  7. Lancer le payload (port 9021 ou autoload.txt) et attendre la vignette.
  8. Démarrer le jeu. Message : « Jeu backporté : <TITLE_ID> » (à partir de 1.7beta11 « Backport appliqué : … » ; pour un dossier de backport, son chemin y figure sans /fakelib). Si des fichiers d'émulateur ont été remplacés au passage, le message l'indique en plus (dans l'original « Emulators updated »). Si seules des bibliothèques d'émulateur sont montées, il indique « Émulateurs appliqués au jeu : … ».
06

Pièges

Huit points où cela coince dans cette version – les trois premiers sont nouveaux par rapport à alpha6.

fakelib2 dans le dossier du jeu dépend de la version

1.7 alpha8 à alpha13fix1 l'ignorent sans message. À partir de 1.7beta1, il l'emporte et masque un fakelib placé à côté – alors sans fakelib globale et sans fichiers d'émulateur. Efficace dans toutes les versions : le renommer en fakelib ou le déposer en tant que backport.

Les fichiers d'émulateur ne font que remplacer

Un fichier de emulators_path n'est repris que si la fakelib du jeu en contient un du même nom. Les nouveaux noms sont ignorés. Pour les PKG installés (à partir de 1.7beta2), rien n'est remplacé.

La globale l'emporte sur l'émulateur

Avec global_fakelib_priority=global, une libSceAmpr.sprx du dossier global l'emporte même sur une version plus récente de emulators_path – la mise à jour automatique d'AMPR n'arrive alors pas jusqu'au jeu.

Un seul jeu à la fois

Lors d'un changement de jeu, l'ancien montage est d'abord nettoyé ; si cela échoue, le nouveau jeu ne reçoit aucune fakelib.

Ne pas modifier la config pendant le jeu

Jusqu'à 1.7 alpha13fix1, toute modification d'une clé fakelib supprime immédiatement tous les overlays – même pendant que le jeu tourne. À partir de 1.7beta1, le montage reste en place jusqu'à la fin du jeu, et les nouvelles valeurs ne s'appliquent qu'au prochain démarrage.

Ne pas utiliser le cache comme dossier global

global_fakelib_path ne doit ni se trouver dans le dossier du cache ni le contenir – cela est refusé.

Sans common/lib, il ne se passe rien

Abandon silencieux : aucun message, aucun montage.

Commentaire obsolète

Dans config.ini.example, le texte relatif à backport_fakelib décrit encore l'ancien comportement avec app0 – dans alpha13fix1 et 1.7beta1. À partir de 1.7beta2, il est corrigé (l'interrupteur ne concerne plus que l'overlay common/lib ultérieur).

08

Quelle version ai-je ?

Trois vérifications rapides – chacune suffit à elle seule.

update_emulators figure-t-il dans config.ini.example ?

oui version récente (alpha8+) — cette procédure
non ancienne version

Le dossier /data/shadowmount/cache/ existe-t-il ?

oui version récente — cette procédure
non ancienne version (ou pas encore besoin de cache)

Le journal contient-il, par jeu, [FAKELIB] using cache for ?

oui version récente — cette procédure
non ancienne version (ou aucun démarrage via le cache jusqu'ici)

Les trois vérifications distinguent l'ancienne version de la nouvelle. Elles ne montrent pas si c'est 1.7 alpha8 à alpha13fix1 ou 1.7beta1 et plus récente qui tourne – les deux ne diffèrent que dans le dossier du jeu (section 02) ; seul le numéro de version le révèle.

ShadowMountPlus 1.7beta11 est fourni (shadowmountplus_v1.7beta11.elf, publiée chez l'auteur comme « Latest »). Elle sait faire tout ce qui est indiqué plus haut comme « à partir de 1.7beta2 », « à partir de 1.7beta3 », « à partir de 1.7beta4 » et « à partir de 1.7beta6 », et lit un fakelib2 dans le dossier du jeu. Nouveau à partir de 1.7beta6 : les dossiers de backport peuvent porter un complément après le Title-ID (voir plus haut) ; l'interface web peut définir par jeu « Ignorer la fakelib globale » (écrit global_fakelib_exclude=<TITLE_ID>, effectif dès le prochain démarrage, le mode de la fakelib propre au jeu reste) ; les applications homebrew en cours d'exécution (quatre lettres majuscules + cinq chiffres, sauf CUSA/PPSA/NPXS) et les jeux PS4/PS5 en cours d'exécution ne ralentissent plus l'analyse et l'enregistrement ; le runtime propre, sa source et ses images montées restent alors protégés. Nouveau dans 1.7beta7 : le nettoyage des couches de sandbox fonctionne aussi après le retrait d'un lecteur USB. Nouveau dans 1.7beta8 : l'interface web a été refaite pour la télévision et la manette, et peut installer des paquets ainsi qu'importer, remplacer et supprimer des backports ; les jeux sont aussi reconnus à un param.sfo (au lieu de param.json) et à un eboot2.bin, et l'interface écoute par défaut sur 0.0.0.0 au lieu de 127.0.0.1. L'ordre et la résolution de la fakelib restent inchangés ici aussi. Nouveau dans 1.7beta10 : l'interface web peut éjecter les lecteurs USB en toute sécurité ; les analyses et les travaux sur d'autres jeux s'exécutent aussi pendant qu'un jeu tourne ; les connexions invité SMB sont réparées et il existe un commutateur invité/authentifié ainsi qu'un mode en lecture seule pour SMB ; les jeux FPKG ne sont plus fermés de force lors de la mise en veille. L'ordre et la résolution de la fakelib restent inchangés. Nouveau dans 1.7beta11 : la file d'attente des PKG est unifiée pour le PC, le stockage local et SMB (sélection de jusqu'à 32 fichiers à la fois, ordre automatique jeu → mise à jour → DLC) ; les erreurs ou interruptions conservent les paquets non terminés ; estimation du temps d'installation restant ; fuites de mémoire corrigées dans json-c. L'ordre et la résolution de la fakelib restent inchangés. Nouveau à partir de 1.7beta5 : chaque jeu a un mode fakelib (fakelib_mode=<TITLE_ID>:default|full|emulators|disabled, valeur par défaut pour tous les autres fakelib_default_mode) ; fakelib_exclude y est considéré comme l'ancien nom de disabled, et la dernière entrée valide d'un jeu l'emporte. « Emulators » ne monte que quelques bibliothèques d'émulateur (pour les paquets installés libSceAppContent.sprx, libSceGameUpdate.sprx et libSceNpEntitlementAccess.sprx, pour les dossiers et les images en plus libSceAmpr.sprx et libScePlayGo.sprx). La documentation ne mentionne qu'à partir de alpha10 qu'un fakelib2 de backport reste exclusif.

À partir de 1.7beta4, avant le démarrage d'un paquet installé, ShadowMount+ supprime libSceAmpr.sprx, libScePlayGo.sprx et libkernel.sprx de /data/homebrew/backports/<TITLE_ID>/fakelib. Cela ne vaut pas pour les jeux provenant d'une image. L'ordre de recherche ci-dessus est inchangé dans 1.7beta4. Dans 1.7beta11, il n'y supprime plus que libSceAmpr.sprx et libScePlayGo.sprx (les fichiers absents sont sans conséquence, une erreur de suppression arrête le montage) ; le dossier de backport peut porter un complément après le Title-ID.

libkernel.sprx (d'après le README et le code source de 1.7beta11) : lorsque fakelib est actif, ShadowMount+ retire ce fichier de la fakelib de dossier inscriptible retenue et de la fakelib globale concernée. Pour les jeux provenant d'une image et pour les paquets installés, la source reste inchangée ; à la place, un cache sans ce fichier est monté. Si ce cache ne peut pas être construit, ShadowMount+ ne monte rien sans filtrage. C'est pourquoi un fakelib2 contenant libkernel.sprx n'est plus dans tous les cas « direct, sans cache ».
