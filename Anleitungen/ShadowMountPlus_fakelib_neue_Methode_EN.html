01

What happens when a game starts

The process starts on its own as soon as the watcher detects a game starting. Lookups no longer happen in the running sandbox but at fixed locations – and a cache is created before mounting.

  1. The watcher reports the PID and TITLE_ID of the game that is starting.
  2. The search follows a fixed order, first the backport folder, then the game source; the first hit wins, and only one folder is ever chosen (section 02).
  3. If it is a fakelib2 – from the backport folder or, from 1.7beta1, from the game – it is mounted directly and exclusively – no cache, no emulator files, no global fakelib.
  4. Otherwise a cache is created under /data/shadowmount/cache/<TITLE_ID>/fakelib/: the game's fakelib, plus the global fakelib and matching emulator files (section 03).
  5. The cache is rebuilt only if one of its sources has changed; otherwise the existing one is used.
  6. It is mounted into the game's sandbox at common/lib.
  7. When the game ends, the mount is removed again.

From this version on, where a folder is located matters, not just what it is called. Reading happens from the backport folder and from the game source itself – no longer from what comes together in the sandbox under app0.

02

Search order

Four locations, in this order. The first existing folder wins – even an empty one; whatever would come after it is ignored.

  1. <scanpath>/backports/<TITLE_ID>/fakelib2/ – wins over everything else and has been mounted exclusively since alpha10.
  2. <scanpath>/backports/<TITLE_ID>/fakelib/
  3. <Spielquelle>/fakelib2/ – only again from 1.7beta1, also exclusive. 1.7 alpha8 through alpha13fix1 skip it without a message.
  4. <Spielquelle>/fakelib/ – works in every version, as long as no fakelib2 sits next to it.
Way A · as a backport, the game stays untouched 
<scanpath>/backports/<TITLE_ID>/
└─ fakelib/
   └─ libSceXxx.sprx

Example:
/data/homebrew/backports/PPSA01234/fakelib/
Way B · in the game dump or image 
<game folder or image contents>/
├─ eboot.bin
├─ sce_sys/param.json
├─ fakelib/    ← works in every version
│  └─ libSceXxx.sprx
└─ fakelib2/   ← do not place it next to it!

Rules

Folder names exactly fakelib or fakelib2, lowercase. In the game folder, 1.7beta1 and newer read fakelib2 first, then fakelib; 1.7 alpha8 through alpha13fix1 read only fakelib there and skip a fakelib2 without a message. The only thing that is safe in every version is therefore a single fakelib folder. In the backport folder, fakelib2 comes before fakelib; if both are there, fakelib2 wins.

The backports folder is skipped during the normal scan. A backport takes effect from any scan path on the matching game; if several scan paths supply the same title, the game's scan path wins, otherwise the order of the scanpath entries decides. Usual locations are /data/homebrew/backports/<TITLE_ID>/ and /data/etaHEN/games/backports/<TITLE_ID>/. From 1.7beta6, a suffix may follow the title ID (backports/<TITLE_ID> Spielname/): within a scan path, the folder named exactly <TITLE_ID> wins; if there is none, ShadowMount+ takes, from the folders whose name begins with the whole title ID, the first one in byte order (upper and lower case count; files do not count). So if a folder with a suffix is accompanied by a folder with the bare name, the one with the suffix is no longer read. From 1.7beta3, /data/homebrew/backports/<TITLE_ID>/ is still searched last – even if custom scanpath entries leave out /data/homebrew. Games are therefore not searched for there.

Installed PKGs (from 1.7beta2): A game installed as a PKG now gets its backport folder <scanpath>/backports/<TITLE_ID>/ too. Shortly before the game starts, ShadowMount+ overlays its entire contents onto the package's app0 – files individually, subfolders that the package does not have as a whole, at most 256 entries per game. The package itself is not modified. After that, fakelib2 or fakelib is mounted as usual. Up to 1.7, an external backport was skipped for installed PKGs; only what was in the package counted there.

When integrating (BACKPORT, AMPR EMU), this program always creates a fakelib folder – it works in both locations and in every version. If a fakelib2 is already in the game, it warns beforehand.

03

Cache, emulators and global fakelib

Instead of stacking layers, ShadowMount+ copies everything into a cache under /data/shadowmount/cache/<TITLE_ID>/fakelib/ before the start. Whatever is copied last wins when the file name is the same – the order is set by global_fakelib_priority.

Default

global_fakelib_priority=game

1 · global→ 2 · game→ 3 · emulator

The game's file prevails over the global one. Emulator files only replace names in it that the game already brings along.

Alternative

global_fakelib_priority=global

1 · game→ 2 · emulator→ 3 · global

The global file wins – even against an emulator file of the same name, which is then not copied at all.

Emulator files (update_emulators=1): A file from /data/shadowmount/emus is only taken over if the game's fakelib has a file of the same name. If a name exists only in the global folder or nowhere, it is skipped. For a game without libSceAmpr.sprx, this route alone therefore achieves nothing. From 1.7beta2, this applies only to games from folders and images – installed PKGs do not get emulator files.

Automatic AMPR update (auto_update_ampr=1, off by default): 30 seconds after startup and every four hours thereafter, ShadowMount+ checks whether a newer libSceAmpr.sprx exists and places it in emulators_path. If it is missing there entirely, it is fetched right away. While a game is mounted, the download waits. It gets into the game via the emulator files – so only if the game's fakelib already contains a libSceAmpr.sprx.

Global fakelib: If there is both a global and a game-specific fakelib, they are combined in the cache. If there is no game-specific one, the global folder is mounted directly. With global_fakelib_exclude, individual titles can be exempted from it.

Since alpha10: A backport fakelib2 is mounted directly and exclusively. Neither emulator files nor the global fakelib replace or add anything there.

The cache is rebuilt as soon as the game's fakelib, the global fakelib or the emulator files change. If a game is not started for seven days, its cache expires.

04

Settings

Everything is in /data/shadowmount/config.ini. The four keys update_emulators, emulators_path, auto_update_ampr and ampr_update_url exist only from alpha8.

KeyDefaultMeaning
backport_fakelib1Master switch. 0 turns everything off – including the global fakelib and the emulator files. Exception from 1.7beta2: for installed PKGs, the backport folder is still overlaid onto app0; the switch only affects the mounting of the fakelib there.
update_emulators1Matching files from emulators_path replace same-named ones in the game's fakelib. A fakelib2 stays unchanged, and from 1.7beta2 so does every installed PKG.
emulators_path/data/shadowmount/emusFolder with the emulator files. They lie directly in it – only what is not inside a subfolder is compared.
auto_update_ampr0Fetch libSceAmpr.sprx from the network on its own: 30 s after startup, then every four hours.
ampr_update_urldrakmor/ampr_emuDownload address for the AMPR update; by default the latest release of github.com/drakmor/ampr_emu.
global_fakelib1Also use the global folder for every detected game. A fakelib2 remains unaffected by it.
global_fakelib_path/data/shadowmount/fakelibLocation of the global folder. The libraries lie directly in it; a subfolder fakelib would be copied along but not mounted. Must not point to the cache.
global_fakelib_prioritygamegame or global – which one wins when the file name is the same (section 03).
global_fakelib_exclude—Repeatable. Exempts titles from the global fakelib; the game-specific one stays active.
fakelib_exclude—From 1.7beta4. Repeatable, up to 128 title IDs (PPSA, CUSA, LAPY, FAKE). From 1.7beta5 only the old name for fakelib_mode=<ID>:disabled (both share the 128 slots; global_fakelib_exclude has its own limit of 128). Switches off every fakelib for these titles – fakelib, fakelib2, the global one and the cache. An AMPR EMU placed there is then not loaded. Takes effect at the next game start.
fakelib_default_modefullFrom 1.7beta5. Mode for all games without their own entry: full, emulators (only a few emulator libraries) or disabled.
fakelib_mode—From 1.7beta5. Repeatable, <TITLE_ID>:default|full|emulators|disabled. The last valid entry for a game wins.

Example

backport_fakelib=1
update_emulators=1
emulators_path=/data/shadowmount/emus
auto_update_ampr=0
global_fakelib=1
global_fakelib_path=/data/shadowmount/fakelib
global_fakelib_priority=game
global_fakelib_exclude=PPSA01234

Accepted values are 1/0, true/false, yes/no, on/off. auto_update_ampr=1 lets the console access the network – by default this is off.

05

Step by step

From zero to the message “Game backported”.

  1. Disable the BackPork payload. Running both in parallel causes conflicts.
  2. Place the game in a scan path – as a folder (with sce_sys/param.json) or as an image.
  3. Create the libraries – for example with this program (BACKPORT or AMPR EMU). It always creates a fakelib folder.
  4. Place them. As a backport under <scanpath>/backports/<TITLE_ID>/fakelib/, the game stays untouched. In the game itself – which is how this program integrates it when creating – only fakelib takes effect.
  5. Optional: global libraries directly into /data/shadowmount/fakelib/, emulator files directly into /data/shadowmount/emus/ – in each case without a subfolder.
  6. Set the config – before the game starts.
  7. Start the payload (port 9021 or autoload.txt) and wait for the tile.
  8. Start the game. Message: “Game backported: <TITLE_ID>” (from 1.7beta11 “Backport applied: …”; for a backport folder, its path without /fakelib appears there). If emulator files were replaced in the process, the message says so in addition (in the original “Emulators updated”). If only emulator libraries are mounted, it reads “Emulators applied to game: …”.
06

Pitfalls

Eight points where things get stuck in this version – the first three are new compared with alpha6.

fakelib2 in the game folder depends on the version

1.7 alpha8 through alpha13fix1 skip it without a message. From 1.7beta1 it wins and hides a fakelib next to it – then without the global fakelib and without emulator files. Effective in every version: rename it to fakelib or place it as a backport.

Emulator files only replace

A file from emulators_path is only taken over if the game's fakelib has a file of the same name. New names are skipped. For installed PKGs (from 1.7beta2), nothing is replaced at all.

Global beats emulator

With global_fakelib_priority=global, a libSceAmpr.sprx in the global folder wins even against a newer one from emulators_path – the automatic AMPR update then does not get through.

Only one game at a time

When switching games, the old mount is cleaned up first; if that fails, the new game gets no fakelib.

Do not change the config during the game

Up to 1.7 alpha13fix1, every change to a fakelib key immediately removes all overlays – even while the game is running. From 1.7beta1, the mount stays in place until the game ends, and the new values only take effect at the next start.

Do not use the cache as the global folder

global_fakelib_path must neither lie inside the cache folder nor contain it – this is rejected.

Without common/lib, nothing happens

Silent abort: no message, no mount.

Outdated comment

In config.ini.example, the text for backport_fakelib still describes the old app0 behavior – in alpha13fix1 and 1.7beta1. From 1.7beta2 it is corrected (the switch now only affects the later common/lib overlay).

08

Which version do I have?

Three quick checks – any one alone is enough.

Is update_emulators in config.ini.example?

yes new version (alpha8+) — this guide
no old version

Does the folder /data/shadowmount/cache/ exist?

yes new version — this guide
no old version (or no cache needed yet)

Does the log contain [FAKELIB] using cache for for each start?

yes new version — this guide
no old version (or no start via the cache so far)

The three checks separate old from new. They do not show whether 1.7 alpha8 through alpha13fix1 or 1.7beta1 and newer is running – the two differ only in the game folder (section 02); only the version number reveals that.

Bundled is ShadowMountPlus 1.7beta11 (shadowmountplus_v1.7beta11.elf, published by the author as “Latest”). It can do everything that is labeled “from 1.7beta2”, “from 1.7beta3”, “from 1.7beta4” and “from 1.7beta6” above, and it reads a fakelib2 in the game folder. New from 1.7beta6: backport folders may carry a suffix after the title ID (see above); the web interface can set “Ignore global fakelib” per game (writes global_fakelib_exclude=<TITLE_ID>, takes effect from the next start, the mode of the game's own fakelib remains); running homebrew applications (four capital letters + five digits, except CUSA/PPSA/NPXS) and running PS4/PS5 games no longer slow down scanning and registration; the runtime itself, its source and its mounted images remain protected in the process. Order and resolution of the fakelib are unchanged. New in 1.7beta7: cleaning up the sandbox layers also works after a USB drive has been unplugged. New in 1.7beta8: the web interface has been rebuilt for TV and gamepad and can install packages as well as add, replace and delete backports; games are also recognized by a param.sfo (instead of param.json) and by an eboot2.bin, and the interface listens on 0.0.0.0 by default instead of 127.0.0.1. Order and resolution of the fakelib are unchanged here as well. New in 1.7beta10: the web interface can safely eject USB drives; scans and work on other games also run while a game is running; SMB guest connections are repaired and there is a guest/logged-in switch as well as a read-only mode for SMB; FPKG games are no longer forcibly closed on sleep mode. Order and resolution of the fakelib are unchanged. New in 1.7beta11: the PKG queue is unified for PC, local storage and SMB (select up to 32 files at once, automatic order game → update → DLC); errors or cancellations keep the packages that are not finished yet; estimate of the remaining installation time; memory leaks in json-c fixed. Order and resolution of the fakelib are unchanged. New from 1.7beta5: there is a fakelib mode per game (fakelib_mode=<TITLE_ID>:default|full|emulators|disabled, default for all others fakelib_default_mode); fakelib_exclude counts there as the old name for disabled, and the last valid entry for a game wins. “Emulators” mounts only a few emulator libraries (for installed packages libSceAppContent.sprx, libSceGameUpdate.sprx and libSceNpEntitlementAccess.sprx, for folders and images additionally libSceAmpr.sprx and libScePlayGo.sprx). That a backport fakelib2 remains exclusive is stated by the documentation only from alpha10.

From 1.7beta4, before the start of an installed package, ShadowMount+ deletes libSceAmpr.sprx, libScePlayGo.sprx and libkernel.sprx from /data/homebrew/backports/<TITLE_ID>/fakelib. This does not apply to games from an image. The search order above is unchanged in 1.7beta4. In 1.7beta11 it deletes only libSceAmpr.sprx and libScePlayGo.sprx there (missing files are harmless, a deletion error stops the mount); the backport folder may carry a suffix after the title ID.

libkernel.sprx (according to the README and source code of 1.7beta11): If fakelib is active, ShadowMount+ removes this file from the selected writable folder fakelib and from the global fakelib involved. For games from an image and for installed packages, the source remains unchanged; instead a cache without the file is mounted. If this cache cannot be built, ShadowMount+ mounts nothing unfiltered. A fakelib2 containing libkernel.sprx is therefore no longer “directly, without cache” in every case.

Applies to ShadowMountPlus from 1.7 alpha8.
